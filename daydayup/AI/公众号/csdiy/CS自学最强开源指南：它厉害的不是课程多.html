CS 自学最强开源指南：它厉害的不是“课程多”，而是帮你少走弯路

如果你正在自学计算机，大概率经历过一种很熟悉的状态：

收藏了 MIT、CMU、Berkeley 的公开课，保存了十几个 GitHub 仓库，网盘里躺着几十本 PDF，浏览器书签栏被“算法”“操作系统”“数据库”“机器学习”“项目实战”塞满。

但真正开始学的时候，问题反而来了：

我应该先学哪门？

这个课程适合现在的我吗？

我学完一门课之后，下一步是什么？

我到底是在搭建能力，还是只是在囤资源？

这就是我觉得 CS 自学指南（https://csdiy.wiki/）值得单独写一篇的原因。它强的地方不只是“资源多”，而是把散落在互联网上的高质量 CS 学习资源，整理成了一张更接近真实学习过程的地图。

资源不稀缺，路径才稀缺

今天自学 CS，最容易产生的错觉是：只要找到更多资料，就能学得更好。

但真正阻碍大多数人的，往往不是资料太少，而是 资料太多、层级不清、先后关系混乱。

比如你想学操作系统，很容易同时看到几类资源：

  • 大学公开课；
  • 教材和讲义；
  • 实验项目；
  • 面试八股；
  • 博客笔记；
  • 视频解说。

它们都可能有价值，但并不适合在同一个阶段使用。刚入门的人直接啃论文和内核源码，很容易被劝退；已经有基础的人只刷短视频总结，又很难真正建立系统理解。

好的学习指南，真正要解决的是“顺序”和“取舍”。

这也是 csdiy.wiki 的核心价值：它不是把所有链接堆在一起，而是按计算机教育里的关键板块组织内容，包括编程入门、数学基础、算法、体系结构、操作系统、计算机网络、数据库、软件工程、人工智能等方向。

更重要的是，它还提供了工具、书籍推荐和学习规划相关内容。也就是说，它默认你不是一个只想“看课”的人，而是一个需要逐步建立学习环境、补齐基础、完成项目、形成输出的自学者。

它为什么能被称为“最强开源”

说一个开源学习项目“强”，不能只看链接数量。

真正有价值的开源教育项目，至少要满足四点：

第一，内容选择要经得起推敲。

CS 自学指南收录的很多课程来自世界知名高校和经典公开课体系。它把这些课程放到具体知识领域里，而不是只做一个“名校课程大合集”。这会减少很多无效选择。

第二，结构要能帮人建立全局感。

自学最怕只见树木、不见森林。你今天刷一点算法，明天看一点数据库，后天听一点 AI，短期很充实，长期却很难形成能力闭环。

csdiy.wiki 的好处在于，它把 CS 看成一个相互关联的系统：数学是底层工具，程序设计是表达能力，算法和系统课程训练抽象与工程理解，数据库、网络、软件工程则把知识推向真实应用。

第三，它必须允许你按自己的节奏走。

传统大学课程有学期、作业、考试和同学压力；自学没有这些外部结构。所以自学者更需要一份可以反复回来校准方向的地图。

你可以从编程入门开始，也可以直接补系统方向；可以按主线推进，也可以为求职、考研、转码、科研分别取用不同模块。

第四，开源意味着它会被持续修正。

CS 自学指南背后对应 GitHub 开源项目 pkuflyingpig/cs-self-learning。截至 2026 年 7 月我查看时，该项目已经拥有约 7.3 万 Star 和 7.9 千 Fork。这类规模不只是“受欢迎”的信号，也意味着它长期接受来自学习者和贡献者的反馈。

当然，开源不等于完美。但在学习资源这件事上，持续更新、公开讨论、可被纠错，本身就是非常重要的质量保障。

它最适合哪几类人

如果你是下面几类人，csdiy.wiki 很可能比零散搜索更有用。

第一类：非科班但想系统补 CS 基础的人。

很多转码、自学开发、AI 应用开发者都有一个共同短板：会用工具，但缺少计算机基础框架。你可能能写业务代码，但一碰到性能、网络、并发、数据库事务、编译环境，就容易只会查报错。

这时，与其一上来追热点，不如把指南里的基础课程当成长期主线。

第二类：科班学生，但学校课程质量或节奏不理想。

不是每个人都能在课堂上遇到足够好的课程设计。一个高质量公开课路线，能帮你对照自己学校课程，补充作业、实验和项目训练。

第三类：已经工作，但想补上系统能力的人。

工作几年后再回头看 CS 基础，会发现很多东西不是“用不上”，而是你之前不知道它们在哪里发挥作用。操作系统、网络、数据库、分布式、编译原理，都会在复杂工程问题里重新出现。

第四类：准备走 AI、系统、后端、基础架构等方向的人。

这些方向越往后走，越不适合只靠工具教程。真正拉开差距的，是数学、算法、系统和工程训练的组合。

怎么用它，而不是收藏它

我更建议把 csdiy.wiki 当成 学习操作系统，而不是资源仓库。

具体可以这样用：

第一步，只选一条主线。

不要同时开十门课。你可以先问自己：接下来三个月，我最想补的是编程基础、算法能力、系统基础，还是某个应用方向？

只要主线确定，就先围绕它推进。其他链接再好，也先放进“以后再看”。

第二步，把课程拆成周计划。

自学最容易失败的地方，是把“我要学操作系统”这种大目标写进计划，然后没有任何可执行动作。

更好的写法是：

本周看完 2 个 lecture，完成 1 次 lab，整理 1 篇笔记，写下 3 个没搞懂的问题。

第三步，不要跳过作业和实验。

CS 学习里，真正改变能力结构的往往不是“看懂”，而是 做出来、调通、解释清楚。

公开视频可以 2 倍速看，但实验不能 2 倍速糊弄。尤其是算法、操作系统、数据库、网络这类课，如果只看视频不做作业，收获会打很大折扣。

第四步，每学完一个模块都要输出。

输出不一定是长文，也可以是：

  • 一篇课程复盘；
  • 一个 GitHub 小项目；
  • 一份实验记录；
  • 一张知识结构图；
  • 一组面试题的深度回答。

没有输出，自学很容易变成“我好像看过”。有输出，才会逼迫你发现理解里的漏洞。

也别把它神化

再好的指南，也不能替代学习本身。

csdiy.wiki 能解决的是“去哪找高质量资源”和“如何理解 CS 学习版图”，但它不能替你完成三件事：

不能替你啃难课。

真正好的课程往往不轻松。你会卡在数学推导、环境配置、实验调试、英文材料和抽象概念上，这是正常的。

不能替你判断个人优先级。

如果你马上要找后端开发工作，数据库、网络、操作系统、项目经验可能优先级更高；如果你想做机器学习，线性代数、概率统计、算法和深度学习课程就更关键。

指南给的是地图，但路线仍然要结合你的目标。

不能替你建立反馈系统。

自学最怕长期没有反馈。你需要通过做题、写项目、参加讨论、投递面试、写文章、请别人 review 代码，获得真实反馈。

没有反馈，学习计划再漂亮，也可能只是自我感动。

我的建议：少收藏，多完成

如果你第一次打开 csdiy.wiki，不要急着把每个页面都看完。

更有效的方式是：

先确定一个方向，选一门核心课，给自己 4 到 8 周时间，完成至少一部分视频、作业和笔记。等你真正走完一个小闭环，再回来扩展下一门课。

CS 自学不是拼谁收藏的公开课更多，而是拼谁能持续把资料变成能力。

所以我愿意把 CS 自学指南 推荐给每一个想认真补计算机基础的人。

不是因为它能让学习变轻松。

恰恰相反，它会让你更清楚地看到：计算机科学这条路到底有多长、每一段该怎么走、自己还欠哪些账。

这才是一个好指南最重要的价值。

它不替你走路，但它能帮你少绕路。
