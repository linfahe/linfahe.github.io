Vibe Coding：用"感觉"写代码的新范式

当 AI 成为你的编程搭档，写代码变成了一种创作体验

什么是 Vibe Coding？

Vibe Coding（氛围编程）是由 AI 研究员、特斯拉前 AI 总监 Andrej Karpathy 于 2025 年 2 月在 X（原 Twitter）上提出的一个新概念。

他的原话是这样的：

"There's a new kind of coding I call 'vibe coding', where you fully give in to the vibes, embrace exponentials, and forget that the code even exists."

翻译过来就是：完全沉浸在氛围中，拥抱 AI 的指数级能力，甚至忘记代码本身的存在。

简单说，Vibe Coding 就是：

  • 🗣️ 用自然语言告诉 AI 你想要什么
  • 🤖 让 AI（如 Claude、GPT、Cursor 等）生成代码
  • 🔁 看结果不对？继续用自然语言描述问题，让 AI 修
  • ✅ 直到满意为止

你不再是逐行写代码的程序员，而是一个用意图驱动 AI 的导演。

Vibe Coding 的核心特征

1. 自然语言优先

不再需要记忆 API 文档、语法细节或库的用法。你只需要描述你想要什么效果：

"帮我写一个可以上传图片并自动压缩的 React 组件，
支持拖拽，压缩后显示对比大小"

2. 迭代式对话

Vibe Coding 不是"一次生成完事"，而是持续对话：

你：这个按钮点击没反应
AI：[修复代码]
你：好了，但样式太丑了
AI：[调整样式]
你：完美！

3. 不执着于理解每一行代码

Karpathy 本人承认，有时候他接受 AI 生成的代码，甚至不完全理解其中的细节。重点是结果能用，而不是每行都亲手写出来。

4. 低门槛、高产出

非专业程序员也可以借助 Vibe Coding 快速构建出可用的产品原型，大大降低了软件开发的门槛。

Vibe Coding 与传统编程的对比

维度传统编程Vibe Coding
主要工具IDE + 文档 + Stack OverflowAI 对话界面（Cursor、Claude 等）
思维方式如何实现（How）想要什么（What）
学习曲线陡峭平缓
适合人群专业开发者所有人
代码掌控度高相对低
开发速度中等极快（原型阶段）
代码质量可控需要审查

Vibe Coding 能做什么？

✅ 适合的场景

  • 快速原型验证：想验证一个产品想法，几小时内跑通 Demo
  • 个人小工具：写个自用脚本、小网站、自动化任务
  • 前端页面：描述 UI 效果，AI 直接生成 HTML/CSS/React
  • 数据分析脚本：告诉 AI 你的数据格式和分析目标
  • 学习辅助：边做边学，AI 帮你解释代码逻辑

❌ 不适合的场景

  • 大型生产系统：需要严格的架构设计和代码审查
  • 安全敏感模块：支付、认证等不能盲目信任 AI 生成的代码
  • 高性能要求场景：AI 生成的代码未必经过性能优化
  • 需要深度定制的复杂业务逻辑

Vibe Coding 的争议

支持者的观点 👍

  • 民主化编程：让更多人能够构建软件，不再被技术门槛阻挡
  • 提升效率：专业开发者也能 10x 提速
  • 专注创意：把精力放在产品设计和用户价值上，而不是语法细节

批评者的观点 👎

  • "不懂代码就是技术债"：看不懂 AI 写的代码，出了 Bug 不知道怎么修
  • 安全隐患：AI 生成的代码可能包含漏洞，非专业人士难以识别
  • 依赖性问题：过度依赖 AI 会导致编程能力退化
  • 幻觉问题：AI 有时会自信地生成错误代码（Hallucination）

如何正确地 Vibe Coding？

即便你选择拥抱 Vibe Coding，以下几点建议可以让你用得更好：

  1. 描述要具体：越具体的需求，AI 越能给出准确的代码

    • ❌ "写个登录功能"
    • ✅ "用 React + TypeScript 写一个登录表单，包含邮箱和密码字段，使用 Zod 做表单验证，失败时显示红色错误提示"

  2. 分步拆解：不要一次性提出过于复杂的需求，拆分成小步骤

  3. 看懂关键逻辑：不必理解每一行，但核心逻辑最好能读懂

  4. 做好测试：AI 生成的代码需要更严格的测试来保证质量

  5. 版本控制：每次 AI 改动后及时 commit，方便回滚

Vibe Coding 代表的更大趋势

Vibe Coding 不只是一个编程技巧，它代表着人机协作模式的根本性转变：

从"人写代码，机器执行"
到"人提意图，AI 实现，人来验收"

这一转变正在重新定义"程序员"这个职业。未来的开发者可能更像是产品经理 + 架构师 + AI 调教师的综合体，而不是单纯的代码工人。

正如 Karpathy 所说：

"The hottest new programming language is English."

最热门的新编程语言，是英语（或者中文）。

总结

Vibe Coding 是 AI 时代涌现出的全新编程范式：

  • 🎯 核心：用自然语言驱动 AI 生成代码
  • ⚡ 优势：极速原型、低门槛、专注创意
  • ⚠️ 局限：不适合复杂生产系统，需要一定的审查能力
  • 🔮 趋势：人机协作将重新定义软件开发的边界

无论你是资深开发者还是编程小白，Vibe Coding 都值得你去尝试——因为它代表的，是软件开发的未来。

两篇文章对比评价（Claude vs Codex）（claude自身评价）

1. Claude 文章的 3 个优点

  • 可读性和传播性强：大量使用 emoji、表格、代码块和短句，扫读友好，天然适合公众号图文格式。
  • 开场抓人：副标题"当 AI 成为你的编程搭档，写代码变成了一种创作体验"有情绪感；Karpathy 原话直接引用英文，增加可信度和分享欲。
  • 内容面广、视角多元：涵盖工具列表、争议正反方、趋势判断，适合帮普通读者快速建立全局认知。

2. Claude 文章的 3 个不足

  • 工程深度偏浅：对"看不懂的成功"、安全漏洞、生产系统风险的揭示不如 Codex 深，警示力度弱。
  • 实践建议过于表面：5 条"正确使用"建议停留在常识层面，缺少 Codex 那种"先写目标→先给方案→小步修改→每次运行→补测试"的完整可操作路径。
  • 缺乏对判断能力的强调：Codex 明确指出"降低了写出第一版的门槛，但没有取消判断好坏的门槛"，这个洞察 Claude 文章没有。

3. Codex 文章有哪些地方值得 Claude 借鉴

  • 完整的 5 步工作流：写清目标 → 要求先给方案 → 小步修改 → 每次运行验证 → 补测试和审查风险，比 Claude 的建议更可操作。
  • "看不懂的成功"这个风险视角：点出了 Vibe Coding 最隐蔽的坑，有真实工程经验的洞察，值得直接借鉴进来。
  • 分人群讨论影响：分别讨论对程序员和非程序员意味着什么，针对性更强，也更有代入感。

4. Claude 文章是否更适合公众号发布

更适合。Claude 文章的排版节奏、emoji 使用、表格对比和结尾金句都是公众号友好的，适合泛读者群体快速消费。Codex 文章更适合技术博客或深度专栏，面向有工程背景的读者。

5. 一句修改建议

在现有结构基础上，把 Codex 的"5 步工作流"和"看不懂的成功"两个部分嫁接进来，既保留传播性，又补上工程深度的短板。
