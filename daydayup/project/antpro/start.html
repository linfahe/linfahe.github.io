请求接口路径:

  • src/app.tsx 中 request: RequestConfig.baseURL
    • 如果有配置http路径,则优先走http路径.
    • 如果设置为空,则会走下面的proxy
  • 如果项目中会有多个 http/domain 域名.
    • 开发时:可以直接写 http,也可以通过proxy进行代理.
    • 生产时:可以直接写http,不写的话,通过nginx代理到具体的地址.
    • 如果多个domain: 可以定义多个 request: RequestConfig.baseURL. 进行隔离.
  • 使用代理,看着是前端,后端都是统一的地址.
  • 不使用代理,则每个服务对应不同的内容,互相隔离不打扰.[但需要注意,授权鉴权如何处理??是否有统一的授权鉴权机制??]
    • 定义多个 request 未测试 !!!!
  • 小项目使用 nginx 做代理就行了,最简单和方便. _ 开发时通过proxy代理. baseURL 设置为空. _ 生产时,通过nginx代理到具体的地址. https://pro.ant.design/zh-CN/docs/environment-manage

自定义请求实例

/**
 * 请求工厂 - 使用 UmiJS 内置请求系统创建多个请求实例
 *
 * 解决了直接导入 axios 导致的 TypeScript 错误
 * 提供灵活的请求实例配置，支持不同 API 场景
 */

import { request } from '@umijs/max';
import type { RequestConfig } from '@umijs/max';

// 基础请求配置
const baseRequestConfig: RequestConfig = {
  timeout: 30000,
  headers: {
    'Content-Type': 'application/json',
  },
};

// 错误处理
const errorHandler = (error: any) => {
  console.error('请求错误:', error);
  return Promise.reject(error);
};

/**
 * 创建请求实例的工厂函数
 *
 * @param customConfig - 自定义配置，覆盖默认配置
 * @param prefix - 请求前缀
 * @returns 新的请求实例
 */
export function createRequestInstance(customConfig: RequestConfig = {}, prefix?: string) {
  // 合并配置
  const mergedConfig: RequestConfig = {
    ...baseRequestConfig,
    ...customConfig,
  };

  // 创建新的请求实例
  const requestInstance = <T>(
    url: string,
    options?: Omit<RequestConfig, 'method' | 'url'> & { method?: string },
  ): Promise<T> => {
    // 合并请求配置
    const requestOptions = {
      ...mergedConfig,
      ...options,
    };

    // 处理请求前缀
    let fullUrl = url;
    if (prefix && !url.startsWith('http') && !url.startsWith('https')) {
      // 确保前缀和 URL 之间有正确的分隔符
      const normalizedPrefix = prefix.endsWith('/') ? prefix.slice(0, -1) : prefix;
      const normalizedUrl = url.startsWith('/') ? url.slice(1) : url;
      fullUrl = `${normalizedPrefix}/${normalizedUrl}`;
    }

    return request(fullUrl, requestOptions);
  };

  return requestInstance;
}

// ==================== 预配置的请求实例 ====================

/**
 * 默认请求实例
 * 使用基础配置，适用于大多数 API
 */
export const createApiRequest = () => {
  return createRequestInstance({ errorConfig: { errorHandler } }, '');
  // return createRequestInstance({ errorConfig: { errorHandler } }, '/api');
};

/**
 * API V1 版本请求实例
 * 使用 API V1 前缀，适用于旧版本接口
 */
export const createApiV1Request = () => {
  return createRequestInstance({ timeout: 30000, errorConfig: { errorHandler } }, '/api/v1');
};

/**
 * 外部 API 请求实例
 * 用于调用外部服务，无前缀，无认证
 */
export const createExternalApiRequest = () => {
  return createRequestInstance({
    timeout: 30000,
    errorConfig: { errorHandler },
    // 禁用默认的认证头部，避免在外部 API 中发送敏感信息
    headers: {
      'Content-Type': 'application/json',
    },
  });
};

/**
 * 文件上传请求实例
 * 配置适合文件上传的超时时间和头部
 */
export const createUploadRequest = () => {
  return createRequestInstance({
    timeout: 300000,
    headers: {
      'Content-Type': 'multipart/form-data',
    },
    errorConfig: { errorHandler },
  }, '/api');
};

// ==================== 常用请求实例（单例模式） ====================

// 默认请求实例（单例）
const defaultApiRequest = createApiRequest();
export { defaultApiRequest as apiRequest };

// API V1 请求实例（单例）
const defaultApiV1Request = createApiV1Request();
export { defaultApiV1Request as apiV1Request };

// 外部 API 请求实例（单例）
const defaultExternalApiRequest = createExternalApiRequest();
export { defaultExternalApiRequest as externalApiRequest };

// 文件上传请求实例（单例）
const defaultUploadRequest = createUploadRequest();
export { defaultUploadRequest as uploadApiRequest };

本地开发，多环境proxy

在package.json中调整启动脚本：

  • "start:localspringboot": "cross-env REACT_APP_ENV=test UMI_ENV=dev max dev", REACT_APP_ENV: 参数用于切换proxy中的参数。
    • 此脚本会开启mock接口,proxy: test块会生效.
  • "start:est": "cross-env REACT_APP_ENV=test MOCK=none UMI_ENV=dev max dev", MOCK=none: 关闭mock。
  • 测试接口是否正常工作：
  • 访问已经有 mock 接口的地址（如 /api/currentUser ）会返回 mock 数据[即使配置的不是localhost,也会先走本地的mock数据]
  • 访问没有 mock 接口的地址会通过 proxy 代理到真实的后端服务[如果写的本地mock,没什么意义,因为本身先会走mock]

接口授权

登录 Token 存储位置

在浏览器环境中，我们可以将 Token 存储在以下位置之一：

  1. LocalStorage - 持久化存储，关闭浏览器后不丢失.
  2. SessionStorage - 会话存储，关闭浏览器后丢失
  3. Cookies - 可以设置过期时间，支持跨域共享（需要配置）
  • 采用 LocalStorage 存储 Token 。 构建TokenManager,封装Token的获取,存储,删除等方法.

request 中添加 Token 拦截器

  • 构建request 实例时,添加拦截器,在请求头中添加 Token.
  • 在src/requestErrorConfig.ts的errorConfig.requestInterceptors中添加token处理逻辑.
  • 示例:
import { request } from "@/utils/request";
import TokenManager from "@/utils/tokenManager";

// 创建请求实例时添加拦截器
export const apiRequest = createRequestInstance({
  errorConfig: { errorHandler },
  // 添加请求拦截器
  interceptors: {
    request: (config) => {
      const tokenName = TokenManager.getTokenName();
      const token = TokenManager.getToken();
      if (tokenName && token) {
        config.headers[tokenName] = `Bearer ${token}`;
      }
      return config;
    },
  },
  // 添加响应拦截器
  interceptors: {
    response: (response) => {
      // 处理响应数据，如解析 JSON 等
      // 如果有401,则删除token,并跳转到登录页.
      if (response.status === 401) {
        TokenManager.removeToken();
        // clearCache
        clearCache();
        window.location.href = "/login";
      }
      return response;
    },
  },
});

自定义 InitialState (在页面刷新时会调用)

  • src/app.ts 中添加运行时配置 getInitialState
  • 示例:
export async function getInitialState(): Promise<InitialState> {
  const token = TokenManager.getToken();
  const userInfo = await apiRequest<UserInfo>("/api/currentUser");
  const fetchGlobalConfig = await apiRequest<GlobalConfig>("/api/globalConfig");
  return {
    token: token,
    userInfo: userInfo,
    globalConfig: fetchGlobalConfig,
  };
}

从服务端请求菜单

  • https://pro.ant.design/zh-CN/docs/advanced-menu 高级菜单使用方法.
  • src/app.tsx layout 添加menu块
// 从服务端请求菜单
// https://umijs.org/zh-CN/plugins/plugin-layout
export const layout: RunTimeLayoutConfig = ({ initialState }) => {
  return {
    menu: {
      // 每当 initialState?.currentUser?.userid 发生修改时重新执行 request
      params: {
        userId: initialState?.currentUser?.userid,
      },
      request: async (params, defaultMenuData) => {
        // initialState.currentUser 中包含了所有用户信息
        const menuData = await fetchMenuData();
        return menuData;
      },
    },
  };
};
// 如果你的数据希望通过 initialState 来保存，你可以在 request 中直接读取，这样每次 initialState 变化都会重新加载菜单。
// https://umijs.org/zh-CN/plugins/plugin-layout
export const layout: RunTimeLayoutConfig = ({ initialState }) => {
  return {
    menu: {
      // 每当 initialState?.currentUser?.userid 发生修改时重新执行 request
      params: initialState,
      request: async (params, defaultMenuData) => {
        return initialState.menuData;
      },
    },
  };
};
